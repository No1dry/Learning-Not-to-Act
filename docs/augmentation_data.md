# 030 v2 action-data export

Implementation and synthetic CPU verification are available. No real HDF, state recovery, download, model, training, or evaluation was run for this delivery. Real export is a user-started stage after source availability and mappings are reviewed. The 180 additional demonstrations remain a maximum candidate budget.

One entry indexes original HDF without copying RGB:

```bash
python -u -m egrs.augmentation.export --manifest <sources.json> --base-inventory <existing-inventory.json> --evidence <trusted-local-evidence.json> --output <new-export-directory>
```

`--evidence` is optional. `--evidence-provider <provider-config.json>` optionally resolves needed local evidence during the same export. These flags can be combined for different source IDs. The output must be new. The code never starts downloads or chooses a simulator by discovery. Without trustworthy evidence, RAW remains available. If both augmentation pools are empty, `report.json` states `augmentation_available=false`; the Progress-Aug trainer must reject this as unavailable augmentation. An empty or partly covered pool never acquires invented 50/25/25 coverage.

## Explicit model-data mapping

Mapping is mandatory per source; a reusable mapping can be copied into source records by the operator. The exporter does not detect action fields, infer t versus t+1, choose signs, or choose normalization. `observation_offset` and `action_offset` state the exact correspondence `o[start+observation_offset] -> a[start+action_offset]`; `alignment_id` and `alignment_basis` identify the verified evidence. HDF observation/action lengths must exactly match the declared full length plus their offsets, preventing accidental RAW truncation. Only mapped current dual uint8 RGB, the ordered eight proprio dimensions, and seven expert action dimensions are read. Simulator state, predicates, contacts, masks, future observations and eval fields are forbidden inputs.

Original processor/crop identity and each camera orientation (`identity` or `rotate_180`) are explicit. No image resize, crop or extra geometry is performed here; training applies the original OFT processor. Ordered axis signs apply to action coordinates. Gripper endpoints explicitly map actual raw open/closed values to OFT target open=1/closed=0; `identity` is accepted only if the field already has those endpoints. `affine` preserves intermediate values; `binarize` uses the midpoint between declared endpoints. Do not select a mapping merely because a fixture uses it.

Action and proprio each use either `bounds_q99` with original q01/q99/mask, or `identity_already_normalized` for a field demonstrably already transformed. Both require the original checkpoint's unnorm key and dataset-statistics file SHA256. Actions are transformed exactly once after gripper conversion; the gripper dimension is excluded from bounds normalization. Proprio follows the original helper: normalize masked dimensions, then clip all dimensions to [-1,1]. Training calls `validate_normalization(original_stats, unnorm_key, stats_sha256)` before use, matching every binding and provided bounds/mask against the loaded original checkpoint. Already normalized declarations still require identities and documented provenance; they cause no second normalization.

## Trusted evidence or RAW fallback

Evidence schema is illustrated by `data_evidence.example.json`. Each record binds `source_id`, exact source file SHA256, `alignment_id`, and official `active_goals`; it names the actual reviewer/verified producer and review basis. Accepted provenance is `reviewed_local_evidence` or `verified_local_sim_evidence`. A status flag or a native false→true goal transition alone does not prove action ownership and is rejected. This small interface consumes trusted reviewed evidence; it does not implement old visual annotation, native physical verification, or automatically certify claims made by an arbitrary producer.

`stages` contains `{start, stop, pending_goals}` in observation/action-index coordinates with stop exclusive. Pending goal IDs may be A,B; A; or B, without assuming A was first. An empty pending set is terminal and adds no stopping targets. Stages must not overlap. PROGRESS retains the full instruction and original expert action target. The sampler balances actual stages using `progress_stage` metadata; this field never appears in model inputs.

`atomic_segments` contains `{start, stop, goal_id, instruction, exclusive_goal_actions: true, review_basis}`. The exact atomic language and the entire continuous action segment must have been reviewed as belonging to that goal, with only its necessary prerequisites/retreat. A goal-transition candidate is insufficient. Whole-compound-trajectory relabeling and overlapping segments are rejected. Atomic chunk8 ends at the skill boundary; remaining positions are zero padding with false loss masks. RAW and PROGRESS tails behave the same way at episode end; no final action is repeated and no episodes are joined.

Invalid evidence is recorded with exclusions and falls back to eligible RAW windows; invalid underlying RAW mapping/source identity stops export. A source may have one usable augmentation view without the other; reports preserve this distinction. Existing trustworthy records are preferred. Sources without evidence do not need perfect annotation before RAW training can start.

## Optional local evidence producer

There is no bundled simulator/recovery implementation. `--evidence-provider` is a minimal explicit adapter for a separately reviewed implementation: a Python module pinned by SHA256 exports `recover(*, requests, sources, data_root) -> list[evidence_record]`. Its producer/dependency lock and actual trust basis are configuration fields. It receives only requested compound sources and named `{source_id, windows:[[start,stop],...], purpose:'stage_anchor_and_skill_boundary'}` requests. Full-trajectory coverage requests are rejected; emitted segment endpoints must lie in the requested local evidence windows. The provider's module hash is checked before import, and producer identity/request config is recorded in the export. The provider is responsible for verified original image/state/action alignment, local restoration correctness, and action ownership; this package cannot prove those from a boolean or hash. No built-in provider currently supplies this physical evidence. Unsupported or unavailable recovery means trusted-file evidence or explicit RAW fallback, never fabricated certainty.

## Exported contract

`sources.json` stores source/group/split and original file/field/time/normalization mapping; `windows.jsonl` stores RAW/PROGRESS/ATOMIC indexes; `evidence.json` retains evidence and producer locks; `report.json` reports exclusions, RAW fallback, each task/split/view window and valid-action count, actual index ratios, progress-stage counts, missing candidate tasks, mapping identities and unknown ancestry. Index ratios describe stored windows, not the training sampler's realized draws. The training loop reports its actual selected ratios separately.

`AugmentationDataset(export_dir, split=None, views=None)` exposes `.rows`, `.sources` and `.report` for offline auditing/sampling. `__getitem__` opens the original HDF on demand and returns exactly `images` (two uint8 numpy arrays), `proprio` (float32[8]), `actions` (float32[8,7]), `action_mask` (bool[8]), and `instruction`. Stage labels, source metadata, goal predicates, evidence, and hidden HDF fields do not enter that item. Masks supervise valid action scalars only. A RAW-only dev dataset uses unchanged complete instructions and no extra augmentation.

CPU verification uses only tiny generated HDF and a synthetic provider. Run `python -m pytest tests/test_augmentation_data.py -q --basetemp <new-local-test-temp-dir>`. Real HDF availability, trustworthy local physical evidence, exact production mappings, source coverage, GPU memory and experiment results remain unverified by these tests.
