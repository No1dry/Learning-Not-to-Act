## Shared interfaces and decisions

Use focused modules under `egrs/offline/`. The exact Python signatures may be finalized by Task 1 and documented in its report before dependent work, but keep these boundaries:

1. **Mapping:** versioned packaged JSON maps each exact instruction / goal_ref / kind to the native atom and explicit target/destination/mechanism evidence requirements. Native names remain annotation-side. At runtime validate BDDL/registry agreement; do not use total task success. Top-drawer g0 Open is explicitly an annotation-only native subgoal because the BDDL final goal contains only bowl In. Cream-cheese-in-bowl uses native On; plate-front uses main_table_stove_front_region.
2. **Alignment:** pure functions evaluate a declared small set of rules (`same_state`, `next_state`, `replay_action`) against fixed existing-frame RGB comparisons and runtime metadata. They record rule, basis, residuals, orientation and boundary policy. No implicit state[i] match, global shift, final-frame clamping or success-based selection. Genuinely different or merely visually similar physical alternatives remain a gap. A next-state/replay pair proven physically equivalent may be coalesced with an explicit representative and auditable state checks covering every frame authorized by that equivalence; the pure validator must recompute acceptance using that evidence. Final replay still requires separate corroboration and boundary handling. Stored RGB is never transformed or replaced.
3. **Frame facts:** versioned JSON-safe operational record binds source_id and physical frame, accepted alignment, per-goal native truth, stable legal entity alias, per-camera *visible* evidence boxes/support availability and conservative grasp/release result. A separate audit record records native names/IDs, hashes and reasons. No full state array is returned. Fact-to-label conversion validates bindings, normalized boxes, kinds and observation support before constructing the existing answer schema.
4. **Worker protocol:** one explicit source request contains its inventory source descriptor, existing requested frame indices, original image paths/dimensions and runtime config; one response contains source inspection/alignment, frame facts, and separate audit/errors. The worker is independent from model workers and lazily imports LIBERO only on the real annotation command. A concrete native adapter must be provided, not only an extension interface. Task 2 defines the serialized request/response interface for Task 3 and supplies a fake-compatible transport boundary.
5. **Controller:** `label-sim --inventory ... --windows ... --registries ... --backend-config ... --output ...` validates frozen inputs before worker launch and copies original records only to attach new answer/provenance. `export-sim --annotations ... --windows ... --attestation ... --output ...` verifies manifest/file hashes and original payload/group/split bindings before calling existing build_dataset with original fixed_source_splits. No automatic teacher/training stage.
6. **Observability:** use target/destination/active-part visible pixels, not whole projected geometry or static cabinet masks. Relation needs relevant relational supports. Interaction uses dual-pad grasp or the existing conservative hand/pinch-clearance release rule plus visible target/hand evidence; a single contact or merely closed fingers is UNKNOWN. HELD never implies RELEASED; mechanism release remains NOT_APPLICABLE. Stable entity aliases are shared across a source's windows. Conservative gaps are preferable to unsupported labels and must be quantified.
