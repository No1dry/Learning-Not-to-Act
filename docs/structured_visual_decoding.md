# 028: token-time visual output shape constraints

The user's real 027 run decomposed the instruction correctly but its first
two-camera prediction omitted both required `evidence` fields. No robot action
was executed. This is a generated-output contract failure, not a task score.

028 adds a required-key, closed-object JSON Schema token filter during visual
generation using pinned `lm-format-enforcer==0.11.3` and `interegular==0.3.3`.
The schema is constructed only from the public language registry, current query
and supplied snapshot identities. Entity IDs, state values, boxes, cameras and
support claims are still generated by the trained model. It does not fill in
omitted evidence, call a teacher, retry automatically or read evaluator truth.

The original semantic validator remains unchanged. In particular a JSON-valid
`MATCHED`/`SAT` claim with empty evidence still fails. Constrained syntax does
not prove visual correctness, field agreement or task success. Raw output,
constraint version/dependency/schema hash and all failures remain audited.

The first real v1 attempt added the keys but produced long decimals and repeated
evidence until reaching the unchanged 1024-token limit. It was retained as a
failure, not repaired into an answer. The v2 grammar uses compact fixed field
order, exactly one row per input goal, up to three evidence regions per goal,
and normalized coordinate literals with at most eight decimal digits. This is
a versioned output-budget restriction, not a claim that all previous 12-region
outputs are representable. Entity/query cross-references echo the model's own
earlier generated ID and an available snapshot, rather than guessing an ID or
borrowing truth. Null association generates UNKNOWN claims and an empty evidence
list; MATCHED still requires generated evidence. No decoded answer is rewritten.

The v2 real call produced complete JSON (448 tokens), but asserted RELEASED
without any region declaring release support. The original validator rejected
it and that raw failure remains unchanged. V3 therefore generates the model's
own evidence before its state values. For a field lacking declared regional
support, only UNKNOWN is allowed during generation (mechanism release remains
NOT_APPLICABLE); supported fields still have all original state alternatives.
This is a disclosed conservative inference rule, not proof of model-intrinsic
confidence and not a post-hoc edit. No support tag, bbox or physical state is
inserted after decoding. The unchanged validator remains the final guard.

The original training/prediction prompts, checkpoint-3, base/adapter weights,
goal-memory rules, frozen OFT and evaluator metrics are unchanged. This is a
versioned inference change, not a new trained checkpoint. Registry generation
retains the verified 027 prompt and its strict original contract.

The user explicitly authorized Codex to run necessary real selector validation
for 028. The exact failed NPZ observation is hash-checked and reused without
simulation restore, rendering or robot actions. Additional cases are selected
deterministically from existing dev inputs, never on predicted success. Real
GPU calls, harness failures and their timing must be disclosed in the result
report; CPU/fake passing alone is not acceptance. Full OFT evaluation remains
user-started, and old 025/026/027 outputs are not overwritten.
