# 040方案：补足预完成状态下的训练父源与动作续接覆盖

2026-11-10，Codex。**方案与预算提案，尚未获数值预算批准；不是启动命令或X实现工单。**

## 1. 本轮只做什么

直接为`stove`、`mug_pudding`、`two_pots`补充此前未用于035/039生成的普通演示父源，按已验收039方法生成真实10续接轨迹。复用所有原数据，只从原SOG10新初始化训练**一组C1、1000更新**，评测固定九任务10/00各90条，与039 C1的58.89%/85.56%比较。

不把重采样S设成必经实验；不同时修改网络、损失、采样权重、训练长度或评分。S保留为日后可选对照，不在本预算中。此次是训练覆盖增强及强基线完善，不声称是已完成的ICML方法创新。

## 2. 为什么选这个方向

- 三个任务00均100%，10为30%/0%/20%；新初态下的剩余任务执行适配值得优先研究，不把差距全归为一种认知机制。
- 白杯现有10训练仅1个父源、3条变体；当前采样已经task→parent→variant分层、任务等概率。缺口主要是可用父源覆盖，不是“白杯轨迹少所以任务被抽得少”。
- 两壶、开炉已有一定监督，但接近目标后的停滞仍明显。增加普通演示父源会带来不同训练场景及真实续接起点；**不保证**一定增加足够有效多样性或提高SR。
- 成果保护仍重要：C1有3条大位移A破坏及2条双壶短暂回退，不能沿用“只有1条重要”的旧归因。新10仍必须满足原成果保护与释放准入，不放宽指标。

纠错及证据见[039分析复核](2026-11-10_task039_analysis_review_corrections.md)、[机器证据](../../collaboration/evidence/040_existing_results_review.json)。

## 4. 如何生成，不引入第二个算法变量

1. 每个新增train父源最多一次normal真实重放，复用039真实张手/撤离收尾；寻找原canonical A真、B假、释放/空手合格的handoff。
2. 每父源最多3个原机器人起点，每起点最多2个既定桥接尝试，合计≤6次10尝试。仍使用039动作续接方法，不从旧normal后半段直接复制动作标签给已回起点的机器人。
3. 只有`two_pots`沿039在新normal首帧之前互换两个同类壶freejoint；不扩大变换allowlist，不改A/B名称/语义，不在过程中teleport，不碰正式bank。
4. H520、收尾最多40步/撤离≤0.10m、原V2准入、5帧真实释放确认、A/K保护及已确认违规规则保持。所有执行动作和T+1 RGB/proprio/状态真实记录；失败与已花尝试保留，不退款或隐式重试。
5. **仅新增合格train10进入ten训练池；对应normal仅用于生成及原pair两端监督，不加入fresh参考池。** 原fresh/raw参考池和原dev保持。这避免同时改变00保持数据分布。
6. 原pair语义保持：同世界、不同机器人姿态，各端自己的动作标签；只交换z，不交换动作。新增索引绑定真实来源/实际条数，不伪造原039身份。

新增不同父源不自动等于不同物理布局；报告实际合格train父组数、每父变体数及已有记录中的初态范围。它们是数据诊断，不新增正式benchmark指标或人工视频评分流程。

| 阶段 | 新上限 | 说明 |
|---|---:|---|
| 普通重放 | ≤60次 | 仅新增train父源，每父一次；dev不花真实生成预算 |
| 10生成 | ≤360次 | 每生成父源3×2槽，合格数不保证；初始化失败/中断计已花槽 |
| 数据准备 | 1组新导出及训练索引 | 用户启动生产命令内完成；复用旧资格，不另跑预检/MVP |

| 正式评测 | 10/00各90，共180条 | 原九任务、来源、评分、双bridge、H520/chunk8/seed7与全视频 |
| 新基线、S、C0、续训、额外seed | 0 | 复用039 C1结果，不暗中扩实验矩阵 |

物理控制上限为(60＋360)×520=218400步，原H内包含收尾。实际生成可能显著少于上限。若没有新增合格**train父组**的10，则不花预算重复训练同一覆盖集合，保留失败原因；有新增即按实际量推进，不凑最低条数，不自动追加预算。

训练耗时参考038单组约3.5小时、039并行每组主体约4.9小时，非当前GPU保证。039生产实际60normal＋99ten约3.5小时；本轮潜在ten更多，不能照抄这个用时承诺，也不为估时另跑性能测试。

## 7. 怎么读结果

只保留两个主指标：全九任务10二元合规SR、00官方SR。对照仍是039 C1的53/90=58.89%、77/90=85.56%。

同时在同一报告列出三个困难任务合计及各任务SR、同episode成功新增/丢失、原wrong_grasp/A-K回退/释放诊断。它们用于解释，不变成新的主指标，不据视频重新改历史分数。

- 10提高且00不降是首选；若10提高但00下降，按用户“10第一、00第二”明确报告取舍，不自动宣称全面升级。
- 可将总体10净增≥3条（+3.33pp）视为实用积极信号，但**不是显著性标准或强制通过门槛**；小幅变化、配对输赢和不确定性如实报告。
- 不要求开炉必须保持不动；三个困难任务谁改善都算实际增益。原六任务若下降，必须计入总体，不用局部改善掩盖。
- 没改善说明本批补覆盖未产生净收益，不证明“数据无用/进度无用/保持无用”；不自动再加数据、更新或seed。
